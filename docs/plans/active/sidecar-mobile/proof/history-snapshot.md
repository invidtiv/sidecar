# Mobile bounded history snapshot proof

Task `td-595a28` adds one owning-host, read-only history snapshot to the reviewed mobile terminal service. The isolated worktree uses integrated main `3dc287939da7ad3c87eab120d206ab1ca104d6bf` as its source baseline. The production corpus and private proof contain synthetic terminal text only. Every proof command clears `TMUX` and `TMUX_PANE`, uses a private socket, config, and state tree, and cleans only its owned server.

## Contract

The client asks for 1 through 600 latest normal-buffer history rows on an existing attachment. It supplies an already-applied output sequence from the current reset generation and the exact applied geometry. The checkpoint may trail newer frames in that reset, so continuous output does not starve an explicit refresh. History is independent of control and does not consume an operation sequence or change the geometry lease.

The owner captures the requested history and the same momentary live grid in one tmux command list using `capture-pane -e -N`. Before and after capture, the service validates the durable managed-shell identity, owner configuration, attachment, reset generation, geometry, and normal-buffer state. Capture metadata independently carries the pane and session identity, tmux server PID and session creation time, geometry, and alternate-screen state. The response is refused if any authority fact changes.

The result is one frozen VT payload with explicit source geometry and delivered history-row count. Autowrap and cursor display are disabled, rows are separated with CRLF, and the last live row has no line advance. A separate terminal emulator sized to the source geometry and configured with exactly the delivered history capacity therefore reconstructs those history rows above the visible grid. The live terminal parser and replacement-frame stream never consume this payload.

Input capture is bounded before allocation. Requests are limited to 600 history rows, retained and normalized VT to 4 MiB, and the complete response remains below the existing 8 MiB JSONL line bound. Empty history is a successful frozen live-grid snapshot. The live frame's `history_size` is an advisory hint and does not suppress an explicit request. Returned `start_line` and `end_line` describe only this capture. Older pagination is deferred until the owner can issue an immutable snapshot token or a proven append/trim revision; `history_size` cannot safely serve as a cursor once tmux trims at its limit.
