Catalog authorization resolved each ordinary managed-shell row through a new `findShellTarget` scan, and each scan rediscovered every registered project's worktrees. The owning catalog therefore crossed the hub's existing eight-second per-owner deadline and the hub correctly discarded that incomplete source.

Its `shellTargetLookup` performs the all-project discovery once and reuses only that immutable candidate scan while authorizing the observation's shell rows. Lifecycle `idle` and attachment refusal do not independently decide visibility. The hub continues requesting unfiltered Project-order snapshots from owners and applies the preference only after authoritative composition, so an older remote owner does not need to understand the additive field. ## Locale-free SSH follow-up

The subsequent signed phone build still omitted Aerie while showing the one ready MarcusBook shell. The phone's persisted query was the intended activity sort with no search, state, host, or provider filter and `show_idle_sessions: false`. Both phone service processes ran the then-current managed binary from `/Users/marcus`, with `TMUX`, `TMUX_PANE`, `TMUX_TMPDIR`, and `XDG_STATE_HOME` absent. Reconstructing the complete phone process environment reproduced the result outside the app: the catalog contained only the remote row even though a direct tmux pane listing returned all 17 local panes.

The causal difference was the SSH command's locale-free environment. With `LANG`, `LANGUAGE`, `LC_ALL`, `LC_CTYPE`, and `TERM` absent, tmux returned 17 nonempty `list-panes` lines but replaced every literal tab in the machine format with `_`. `workspaceinventory.Collector.ListPanes` therefore parsed no local panes and silently projected every durable shell into the shared `No Session` group, which the explicit false idle preference correctly hid. Setting a UTF-8 locale restored the rows; setting only `TERM=dumb` did not. Running the same tmux client with its `-u` UTF-8 option emitted exactly the locale-present bytes, including tabs and Unicode.

Commit `bfed83fbc333998e48cbcca58915c69a3141ccab` routes machine-output tmux clients through `tmuxformat.ClientArgs`, which adds `-u`. The covered paths are global pane inventory, exact mobile target inspection, the persistent control-mode client, current and historical captures, pane state, and lease reads. A malformed nonempty pane inventory now returns an error rather than becoming a false empty inventory. The private tmux regressions remove `LANG`, `LC_ALL`, `LC_CTYPE`, and `TERM` and prove UTF-8 inventory, exact target identity, capture and History metadata, and control responses. The existing observer measurement was also updated to recognize the intentional `tmux -u -C attach-session` process title while retaining its same-parent and control-client checks.

The independently reviewed before-and-after owner-only proof used the locale-free environment and no terminal action. The previous installed binary returned zero Aerie rows in 0.366 seconds; the source-frozen candidate returned all 17 Aerie rows ready in 1.058 seconds with no failures. The focused race selection passed for `tmuxformat`, `workspaceinventory`, `tty`, `mobile`, and `cli`; the control-client measurement passed three consecutive runs; `go test ./...`, `go build ./...`, and the pinned Linux lint then passed, with zero lint issues. Managed installation activated `bfed83fb` at `/Users/marcus/.local/state/sidecar/dev-installs/main-56680c558beb-bfed83fb-20260908T201222Z-8595/sidecar`. A fresh installed locale-free query returned 18 ready rows: 17 local Aerie rows and one remote row, with both hosts online and no failures. The default tmux server remained PID 98933 throughout.
