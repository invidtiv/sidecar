# Aerie live mobile catalog recovery

On 2026-09-08 the normal mobile hub reported Aerie unavailable and omitted its rows even though desktop Sidecar showed 17 live managed shells. Read-only local and strict `BatchMode` SSH checks resolved the same `/private/tmp/tmux-501/default` socket and tmux server PID 98933, ruling out an SSH namespace mismatch. The installed hub returned only MarcusBook rows plus `local:aerie: context deadline exceeded`, while the same installed owner-only service returned 65 local rows with all 17 live shells ready in 8.6–8.8 seconds.

An instrumented owner query across 24 configured projects and 17 live shells observed 500 Git worktree-list calls. Catalog authorization resolved each ordinary managed-shell row through a new `findShellTarget` scan, and each scan rediscovered every registered project's worktrees. The owning catalog therefore crossed the hub's existing eight-second per-owner deadline and the hub correctly discarded that incomplete source.

Commit `9ab5d62ea73c92a78551afe3a84cb6505b866714` gives each catalog observation one request-scoped ordinary-shell resolver. Its `shellTargetLookup` performs the all-project discovery once and reuses only that immutable candidate scan while authorizing the observation's shell rows. Resolve, open, input, resize, heartbeat, history, and reconnect retain their existing fresh source and identity checks. The post-fix instrumented query performed 52 Git calls total: 24 configured-project inventory reads plus one 28-registered-project target scan, independent of the 17 shell count. It completed in 3.428 seconds under instrumentation; the uninstrumented owner query completed in 1.397 seconds and returned 60 rows with all 17 live shells ready.

The same commit adds the optional `catalog_query.show_idle_sessions` Boolean. Omission preserves the legacy all-row query, explicit `false` excludes only the shared `No Session` group used by desktop Sessions, and explicit `true` includes that group. Lifecycle `idle` and attachment refusal do not independently decide visibility. The hub continues requesting unfiltered Project-order snapshots from owners and applies the preference only after authoritative composition, so an older remote owner does not need to understand the additive field. The canonical 12-case producer fixture is `testdata/mobile-protocol/v0/sessions-catalog.json`, SHA-256 `065555be6d7ea4a225c3095c827c1d4e230b1e9e8ebb45af16d01b6135f6148c`.

The final reviewed candidate was exercised through strict normal SSH to Aerie. Its first `show_idle_sessions:false` query completed in 1.427 seconds and returned 17 Aerie rows, all live and attachment-ready, while the cold MarcusBook route remained explicitly connecting. A second query on the same service process completed in 2.915 seconds and returned the same 17 Aerie rows plus the one live MarcusBook row, all ready and with no failures. After the full repository tests, build, and lint passed, managed install activated clean main revision `040c6b5831851a8dd4ba0ab7add82d93545dcb31`, a documentation-only descendant of the product commit. A fresh normal installed SSH query completed in 1.146 seconds with all 17 Aerie rows live and ready. The default tmux server PID was 98933 before and after installation and proof; no terminal was opened, controlled, resized, or given input.
