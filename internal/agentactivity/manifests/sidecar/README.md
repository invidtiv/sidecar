# Sidecar overlays

An overlay is a file in the same manifest grammar as `../upstream/<agent>.toml`, named `<agent>.toml`, carrying only what Sidecar believes it does better than upstream. It is merged over the vendored manifest by rule id: `disable = true` removes the upstream rule with that id, a rule whose id matches an upstream id replaces it, and any other rule is appended. Overlay rule ids are prefixed `sidecar.` so an upstream rule can never collide with a Sidecar addition by accident. The merged result is validated with exactly the same limits as a plain manifest. This is why the vendored files are never edited: a re-sync is then a clean file replacement, and an overlay's diff against upstream is the exact list of things we believe we do better.

Four overlays are vendored today, and all four exist for one reason: Rust's `regex` crate supports Unicode binary properties by name and Go's RE2 does not, so upstream's `\p{Alphabetic}` in `antigravity`, `cursor`, `kiro` and `qodercli` cannot compile here. Each overlay carries the same rule id with `[\p{L}\p{Nl}]` in its place, which matches every screen the original targets and differs only for a word beginning with a combining mark. Without them those four rules would be permanently dead in Sidecar; `TestOverlaysMakeEveryRuleCompilable` is what says they are not. Delete an overlay the day upstream stops using the property.

Sidecar-owned *detection* overlays — the rules we believe we do better — arrive with the per-provider cutover in Phase 2; see `docs/plans/active/herdr-detection-parity.md`.
