# Sidecar overlays

An overlay is a file in the same manifest grammar as `../upstream/<agent>.toml`, named `<agent>.toml`, carrying only what Sidecar believes it does better than upstream. It is merged over the vendored manifest by rule id: `disable = true` removes the upstream rule with that id, a rule whose id matches an upstream id replaces it, and any other rule is appended. Overlay rule ids are prefixed `sidecar.` so an upstream rule can never collide with a Sidecar addition by accident. The merged result is validated with exactly the same limits as a plain manifest. This is why the vendored files are never edited: a re-sync is then a clean file replacement, and an overlay's diff against upstream is the exact list of things we believe we do better.

Seven overlay files are vendored today, carrying nineteen rules. Four of those rules exist for one reason: Rust's `regex` crate supports Unicode binary properties by name and Go's RE2 does not, so upstream's `\p{Alphabetic}` in `antigravity`, `cursor`, `kiro` and `qodercli` cannot compile here. Each overlay carries the same rule id with `[\p{L}\p{Nl}]` in its place, which matches every screen the original targets and differs only for a word beginning with a combining mark. Without them those four rules would be permanently dead in Sidecar; `TestOverlaysMakeEveryRuleCompilable` is what says they are not. Delete an overlay the day upstream stops using the property.

The other fifteen are Sidecar-owned *detection* rules kept or added through the Phase 2 per-provider cutover: fourteen `sidecar.`-prefixed additions and one `disable = true` (codex's `osc_title_idle`, whose whole matcher is `\S` on the title and which tmux's seeded `#{pane_title}` therefore satisfies on essentially every pane). Every one of them has a fixture in `../../testdata/`, states in its own comment which upstream priorities it sits between and why, and says what would make it deletable. `docs/reference/herdr-detection-parity.md` ("Phase 2 cutover: the remaining eight providers") is the table of all of them; `docs/plans/active/herdr-detection-parity.md` is the plan.

Three things are worth knowing before adding one.

An overlay rule is a claim that upstream is wrong or silent about a screen you have *captured*. Three rules were deleted rather than carried in the cutover precisely because they had no capture behind them: they retained the pane's state on words like "transcript" or "select a model" for providers nobody had ever seen render such an overlay. A retain rule that fires on a screen the provider may not paint freezes the badge for two minutes on nothing.

`scripts/herdr-diff.sh` is the standing check that each rule still earns its place: a `sidecar.` rule that reaches the same verdict Herdr reaches without it is reported as **redundant** and fails the run. A rule whose only effect is a title-versus-screen conflict cannot be judged there — the harness blanks the title on both sides — and declares itself with a `# harness-exempt: sidecar.<id> — reason` line.

`scripts/herdr-diff.sh --merged` runs Herdr's own engine against the merged manifest, which is how these rules are checked to be *data* rather than a second engine: at the end of Phase 2, 49 of 50 fixtures reach an identical verdict on both engines, and the one that does not is an agent Herdr 0.8.2 has no manifest for.
